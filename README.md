# 📻 WORMADI – วอมาดิ คุยปุ๊บ งานเดินต่อ (เดิมชื่อ Factory Talk / วอภายใน)

ต่อยอดจากเดโม `walkie-demo.zip` (ไฟล์ต้นฉบับยังเก็บไว้ในโฟลเดอร์นี้) มี 3 วิธีใช้งาน โค้ดหน้าเว็บชุดเดียวกัน:

| วิธี | เหมาะกับ | ปิดจอแล้วยังได้ยิน |
|---|---|---|
| **A. เว็บแอป (PWA) บน Cloudflare** ← ใช้งานอยู่ตอนนี้ (ครบ 16 หน้า) | ทุกคน แค่เปิดลิงก์แล้วกดติดตั้ง | ⚠️ ไม่แน่นอน (ดูหัวข้อ 0.5) |
| B. เซิร์ฟเวอร์ใน LAN (`server/`) | ไม่มีอินเทอร์เน็ต | ⚠️ เหมือน A |
| C. แอป Android (`app/`) | เครื่องที่ต้องได้ยินตอนจอล็อกแน่นอน | ✅ (foreground service) |

## 0. WORMADI บน Cloudflare (เวอร์ชัน 2 ตามต้นแบบ 16 หน้า)

### 0.1 ใช้งาน
- ลิงก์: **https://walkie.boboapp2020.workers.dev**
- เข้าสู่ระบบด้วย **รหัสพนักงาน + รหัสผ่าน** ของแต่ละคน ผู้ดูแลระบบเป็นคนสร้างบัญชีให้ที่ **ตั้งค่า → จัดการระบบ (Admin) → + เพิ่มพนักงาน**
- บัญชีผู้ดูแลระบบคนแรก: รหัสพนักงาน `admin` (รหัสผ่านแจ้งในแชท) เข้าแล้วให้เปลี่ยนรหัสผ่านที่ **ตั้งค่า → ข้อมูลส่วนตัว → เปลี่ยนรหัสผ่าน**
- ลืมรหัสผ่าน admin: `cd cloudflare` แล้วรัน `node scripts/create-user.js --emp admin --name "ผู้ดูแลระบบ" --role admin` จะได้รหัสใหม่
- เชิญเพื่อน: **ตั้งค่า → เชิญเพื่อนร่วมทีม** แสดง QR ของลิงก์แอป

#### พนักงานจากรายชื่อ (Google Sheet)
- นำเข้าแล้ว **72 คน** จาก 9 หน่วย: ลูกหีบ 9, หม้อต้ม 8, หม้อเคี่ยว 6, หม้อปั่น 8, หม้อไอน้ำ 14, ไฟฟ้าผลิต 9, ซ่อมบำรุงไฟฟ้า 9, ซ่อมบำรุงเครื่องกล 8, จป. 1 (ในชีตชื่อ "งานความปลอดาภัย")
- **ชื่อผู้ใช้ = รหัสพนักงาน, รหัสผ่านเริ่มต้น = `1234`** เข้าครั้งแรกระบบบังคับตั้งรหัสใหม่ (อย่างน้อย 6 ตัว ห้ามซ้ำ 1234) ก่อนจะใช้เมนูอื่นหรือเข้าช่องวอได้
- ช่องหลักตั้งให้อัตโนมัติ: ลูกหีบ/หม้อต้ม/หม้อเคี่ยว/หม้อปั่น → ฝ่ายผลิต · หม้อไอน้ำ/ไฟฟ้าผลิต → โรงไฟฟ้า · ซ่อมบำรุงไฟฟ้า/เครื่องกล → ซ่อมบำรุง (M&E) · จป. → ความปลอดภัย
- ทุกคนเป็นสิทธิ์ "ผู้ใช้งานทั่วไป" — ตั้งหัวหน้างานได้ที่ **จัดการระบบ → สิทธิ์**
- เพิ่มคน/อัปเดตรายชื่อ: export ชีตเป็น CSV ไปทับ `cloudflare/data/staff.csv` แล้ว `cd cloudflare` → `node scripts/import-staff.js` (ดูก่อนได้ด้วย `--dry`) คนที่มีบัญชีแล้วจะอัปเดตชื่อ/หน่วยเท่านั้น รหัสผ่านไม่ถูกรีเซ็ต · แก้รายการหน่วยที่นำเข้าได้ที่ตัวแปร `UNITS` ในสคริปต์
- พนักงานลืมรหัส: admin กด **รีเซ็ตรหัส** ในหน้าจัดการระบบ คนนั้นจะต้องตั้งรหัสใหม่อีกครั้งตอนเข้า
- ⚠️ รหัสพนักงานเดาได้ และ 1234 เป็นรหัสที่ทุกคนรู้ บัญชีที่ยังไม่เคยเข้าใช้จึงเสี่ยงถูกคนอื่นเข้าก่อน ควรให้ทุกคนเข้าครั้งแรกให้เร็ว (ระบบล็อก 10 นาทีหลังใส่ผิด 5 ครั้ง) และถ้าต้องการปิดไม่ให้คนนอกเห็นเว็บเลย ให้เปิด Cloudflare Access ครอบโดเมน

#### อัปเดตล่าสุด (12 พ.ย. 2026)
- **ห้องสื่อสาร**: ลบห้องเดิมทั้งหมดแล้ว พนักงานสร้างห้องเองได้ที่ เมนู กลุ่ม → สร้างห้องใหม่ (ตั้งรหัสห้องหรือไม่ก็ได้ ใส่รหัสครั้งเดียวแล้วจำไว้) คนสร้างหรือ admin ลบห้องได้ · สูงสุด 10 ห้องต่อคน
- **ลบข้อมูลการพูด**: ลบรายการพูด แชท และ log เดิมทั้งหมดแล้ว (บัญชีพนักงานยังอยู่ครบ)
- **SOS**: กดค้างปุ่มเดียว 1 วินาที ไม่ต้องเลือกประเภท ทุกเครื่องที่เข้าสู่ระบบมีเสียงไซเรน พร้อมชื่อและหน่วยของคนแจ้ง ตำแหน่ง GPS และปุ่มนำทาง
- **แผนที่จริง**: ภาพดาวเทียม/แผนที่ถนน (Esri / OpenStreetMap) แสดงตำแหน่ง GPS ของเครื่อง จุดเหตุ SOS ที่ยังเปิดอยู่ และหมุดสำคัญ · admin กด ✎ แล้วแตะแผนที่เพื่อเพิ่มจุด ลากเพื่อย้าย · หมุดเดิม 4 จุดยังไม่มีพิกัด ต้องวางใหม่
- **รูปโปรไฟล์**: แตะรูปตัวเองที่หน้าหลัก หรือ ตั้งค่า → เปลี่ยนรูปโปรไฟล์ (ถ่ายรูป / เลือกจากคลังภาพ / ลบ) มีตัวอย่างก่อนบันทึก
- **ติดตั้งลงหน้าจอ**: แถบ "ติดตั้ง WORMADI" ที่หน้าเข้าสู่ระบบและหน้าหลัก · เปิดจาก LINE จะเด้งไปเบราว์เซอร์ให้อัตโนมัติ · iPhone มีขั้นตอนแนะนำ
- **ฟังต่อเมื่อพับแอป**: เปิดเป็นค่าเริ่มต้น (Android Chrome/แอปที่ติดตั้ง) · iPhone ระบบหยุดเสียงเมื่อพับแอปนาน ต้องเปิดแอปค้างไว้ · แอป Android (APK) ฟังได้แน่นอนที่สุด
- **ลิงก์หลัก: https://wormadi.pages.dev** (`cloudflare/pages` ส่งต่อไป Worker "walkie") · ลิงก์ workers.dev เดิมพามาที่นี่อัตโนมัติ
  - เครือข่ายที่ทดสอบบล็อกที่อยู่หนึ่งในสองของ pages.dev (172.66.46.243) ถ้าการเชื่อมต่อค้าง แอปจะสลับไปทางสำรอง (workers.dev) เองโดยผู้ใช้ไม่เห็น · ถ้าอยากให้ตรงที่สุด ให้ IT อนุญาต 172.66.46.243 พอร์ต 443
- **ฟังย้อนหลัง**: เปิดแล้วโดยไม่ต้องใช้ R2 — เสียงบีบอัด (μ-law 8 kHz ≈ 8 KB/วินาที) เก็บใน D1 ตาราง audio_clips ลบอัตโนมัติหลัง 7 วัน · ข้อความและ log เก็บ 30 วัน (`RECORDING_RETENTION_DAYS`, `LOG_RETENTION_DAYS` ใน wrangler.jsonc)
- **พิมพ์ข้อความ**: ในห้อง (เมนู ข้อความ หรือปุ่ม "พิมพ์ / ฟังย้อนหลัง" ใต้ปุ่มพูด) พิมพ์แล้วปุ่มไมค์เปลี่ยนเป็นส่ง
- **แชร์ห้อง**: ปุ่ม ➤ ที่รายการห้อง หรือ "แชร์ห้อง" ใต้ปุ่มพูด ได้ลิงก์ + QR + ส่งเข้า LINE ได้ เปิดลิงก์แล้วเข้าห้องทันทีหลังเข้าสู่ระบบ (ห้องมีรหัส ต้องบอกรหัสแยก)
- **วอหาส่วนตัว**: สมาชิกทีมงาน → แตะคนที่ออนไลน์ → "วอหาส่วนตัว" อีกฝ่ายมีเสียงเรียก รับ/ไม่รับ (30 วินาที) คุยกัน 2 คน คนอื่นเข้า/ฟังย้อนหลังไม่ได้ · กด "วางสาย" กลับห้องเดิม
- **เพิ่มรายคน**: ชาญเฉลิม 19464, วีระศักดิ์ 33258, พูโขง 18853, คำตัน 19015, สุรศักดิ์ 19431, ศรัญย์พงษ์ 19430 (ตัวแปร EXTRA_EMP ใน scripts/import-staff.js) · ปุ่ม "สแกน QR เพื่อเข้าใช้งาน" เอาออกแล้ว
- **เก็บบันทึกการสื่อสาร 3 วัน**: เสียง แชท และ log ลบอัตโนมัติทุกคืน (ตี 3) เมื่อเก่ากว่า 3 วัน
- **ได้ยินเสียงเมื่อพับ / ปิดแอป** (ตั้งค่า, เปิดเป็นค่าเริ่มต้น ปิดเองได้)
  - แอป Android (APK): ได้ยินแม้พับแอป ปิดจอ หรือปัดปิดแอปทิ้ง (บริการเบื้องหน้า + การแจ้งเตือน "ออกจากช่อง")

  - iPhone: ได้ยินขณะพับชั่วครู่ iOS หยุดเว็บแอปเมื่อพับนาน (ต้องทำแอป iOS แยก)

## 2. งานที่ 2: สถาปัตยกรรมแอป Android

```
 ┌──────────── แอป (WebView) ────────────┐        ┌────── WalkieService (foreground) ──────┐
 │ index.html เดิม                        │  คำสั่ง │ WebSocket เส้นเดียว (OkHttp, ping 15 วิ) │
 │ ตรวจพบ Capacitor → ไม่เปิด WebSocket    │───────▶│ AudioRecord → ส่ง PCM 16 kHz            │──▶ server.js
 │ ไม่ใช้ WebAudio                          │◀───────│ AudioTrack ← เล่นเสียงขาเข้า + เสียงบี๊บ   │◀──
 │                                        │  event │ การแจ้งเตือนค้าง, WakeLock, WifiLock      │
 └──────────── WalkiePlugin ──────────────┘        │ MediaSession (ปุ่มหูฟัง), ปุ่ม rugged     │
                                                    │ reconnect แบบ exponential backoff        │
                                                    └─────────────────────────────────────────┘
```

- **มี WebSocket เส้นเดียว** อยู่ใน service เท่านั้น ในแอปหน้าเว็บไม่เปิด WebSocket และไม่ใช้ไมค์ของ WebView แค่ส่งคำสั่ง (`join`, `pttDown`, `pttUp`, `switchChannel`, `leave`) แล้วรับ event กลับ
- ปิดแอป ปัดทิ้ง หรือจอล็อก service ยังทำงานต่อ เปิดแอปกลับมาหน้าเว็บจะดึงสถานะล่าสุด (`getStatus`) แล้วแสดงช่องและคนพูดต่อได้ทันที
- **Foreground service** ประเภท `microphone|mediaPlayback` เริ่มตอนกด "เข้าช่อง" ขณะแอปอยู่หน้าจอ ตามกฎ Android 14 ที่ต้องเริ่ม FGS ไมค์จาก foreground ถ้ายังไม่ได้รับสิทธิ์ไมค์ จะเริ่มเป็น mediaPlayback อย่างเดียว (ฟังได้ พูดไม่ได้)
- **การแจ้งเตือน** แสดงชื่อช่อง และ "🟢 X กำลังพูด" / "🔴 คุณกำลังพูด" / "พร้อมรับฟัง · N คน" / "กำลังเชื่อมต่อใหม่…" มีปุ่ม **ออกจากช่อง** และ **กดพูด/หยุดพูด** (กดครั้งเดียวเพื่อเริ่ม กดอีกครั้งเพื่อจบ ใช้ได้จากหน้าจอล็อก)
- **WakeLock แบบ PARTIAL** ถือไว้ตลอดที่อยู่ในช่อง และ **WifiLock** `WIFI_MODE_FULL_HIGH_PERF` (Android ไม่มี WifiLock แบบ partial และ Android 14+ ประกาศเลิกใช้โหมดนี้แล้ว ระบบอาจไม่สนใจ ด่านที่ช่วยจริงคือ FGS + ยกเว้นการประหยัดแบต + ping)
- **Reconnect** รอ 1 → 2 → 4 → 8 → 16 → 30 วินาที (สุ่มบวกลบ 20%) รีเซ็ตเมื่อเข้าช่องสำเร็จ ถ้าระบบแจ้งว่าเน็ตกลับมาจะต่อใหม่ทันทีโดยไม่รอ ถ้าเน็ตหลุดจะตัด socket ทิ้งเลย ไม่ต้องรอ ping หมดเวลา
- **สิทธิ์**: ขอ `RECORD_AUDIO` และ `POST_NOTIFICATIONS` (Android 13+) ตอนกดเข้าช่อง ส่วน `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MICROPHONE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `WAKE_LOCK` ประกาศใน manifest (ระบบอนุญาตตอนติดตั้ง)
- **หน้าตั้งค่าเครื่อง** (ลิงก์ "ตั้งค่าเครื่อง" และเปิดเองครั้งแรกหลังเข้าช่อง): แสดงสถานะการประหยัดแบต มีปุ่มเปิดกล่องยืนยันของระบบ "ให้แอปทำงานเบื้องหลังตลอด" มีคำแนะนำเพิ่มตามยี่ห้อ (Samsung, Xiaomi, OPPO, vivo, Huawei) แสดงสถานะสิทธิ์ และสวิตช์ปุ่มกดพูด
- **ปุ่มกดพูดแบบไม่ต้องเปิดจอ**
  - ปุ่ม play/pause ของหูฟังมีสาย (และปุ่มหูฟัง Bluetooth) ผ่าน `MediaSession` **เปิดไว้เป็นค่าเริ่มต้น**
    - กดค้าง = พูด ปล่อย = จบ
    - กดสั้น (< 0.4 วิ) = เริ่มพูดค้างไว้ กดอีกครั้ง = จบ (หูฟัง Bluetooth ส่วนใหญ่ส่งแค่กดแล้วปล่อยทันที จึงใช้แบบนี้)
  - มือถือ rugged **ปิดไว้เป็นค่าเริ่มต้น** รับ broadcast ของ Samsung Knox (`HARD_KEY_REPORT`), Sonim (`PTT_KEY_DOWN/UP`), `android.intent.action.PTT.down/up` และ keycode 1015/1079 (ปุ่ม XCover) ตอนเปิดแอปอยู่ ที่ปิดไว้ก่อนเพราะ broadcast พวกนี้แอปอื่นในเครื่องส่งปลอมมาสั่งให้เปิดไมค์ได้
- **ตั้งที่อยู่เซิร์ฟเวอร์ในแอป** รับได้หลายแบบ: `192.168.1.10:3000`, `192.168.1.10` (พอร์ต 3000), `wss://host:3000`, `ws://host:3000`
  - ถ้าไม่ใส่ scheme แอปจะลอง https ก่อน ถ้าเซิร์ฟเวอร์เป็น http ธรรมดาจะสลับให้เอง
  - กด "ตรวจสอบ" เพื่อดึงรายชื่อช่องและบอกว่าเชื่อมต่อแบบเข้ารหัสหรือไม่
- **wss แบบ self-signed** ใช้วิธี *trust on first use* ไม่ได้เชื่อทุกใบรับรอง
  1. ครั้งแรกแอปแสดงลายนิ้วมือ SHA-256 ให้เทียบกับที่หน้าจอเซิร์ฟเวอร์พิมพ์ไว้ (`cert SHA-256 ...`) แล้วจึงกด "เชื่อถือใบรับรองนี้"
  2. แอปจำ (pin) ใบรับรองนั้นไว้ต่อ host:port ถ้าภายหลังใบรับรองเปลี่ยน จะไม่ยอมต่อ และแจ้งให้ยืนยันใหม่
  3. ใบรับรองที่ระบบเชื่อถืออยู่แล้ว (จาก CA จริง) ใช้ได้เลย ไม่ต้อง pin

แอป Android ใช้ `ws://` ธรรมดาได้ ไม่ต้องมี HTTPS (ไมค์ทำงานในแอป native) แต่ถ้าต้องให้มือถือเปิดผ่านเบราว์เซอร์ด้วย หรือต้องการเข้ารหัส:

```bash
npm run cert
```

จากนั้น `npm start` ใหม่ หน้าจอจะพิมพ์บรรทัด `cert SHA-256 (ตรวจให้ตรงกับในแอป): AB:CD:...` ไว้ใช้เทียบในแอป

เปิด Windows Firewall ให้ Node.js รับการเชื่อมต่อขาเข้าที่พอร์ต 3000 บนเครือข่าย Private

ทดสอบโปรโตคอลอัตโนมัติ: `npm test` (เปิดเซิร์ฟเวอร์ชั่วคราวที่พอร์ตสุ่ม)

## 4. วิธี build APK ทีละขั้น (Windows)

### 4.1 เตรียมเครื่อง (ครั้งเดียว)
1. ติดตั้ง **Node.js 22 ขึ้นไป** (Capacitor 8 ต้องการ; ทดสอบกับ 24)
2. ติดตั้ง **Android Studio** เวอร์ชันล่าสุด ตอนติดตั้งให้เลือก Android SDK ด้วย (Android Studio มี JDK 21 มาให้แล้ว)
3. เปิด Android Studio → **More Actions → SDK Manager** แล้วติ๊ก **Android SDK Platform 36** และ **Android SDK Build-Tools** เวอร์ชันล่าสุด จากนั้นกด Apply

### 4.2 Build ด้วย Android Studio (ง่ายสุด)
```bash
cd app
npm install
npm run sync
npm run open
```
- `npm run sync` คัดลอก `server/public/index.html` เข้าแอป แล้วรัน `cap sync`
- `npm run open` เปิดโปรเจกต์ใน Android Studio

1. รอ Gradle sync เสร็จ (ครั้งแรกจะดาวน์โหลดไลบรารีหลายนาที)
2. เมนู **Build → Generate App Bundles or APKs → Generate APKs** (บางเวอร์ชันชื่อ **Build → Build APK(s)**)
3. เสร็จแล้วกด **locate** ไฟล์จะอยู่ที่ `app/android/app/build/outputs/apk/debug/app-debug.apk`

### 4.3 Build ด้วย command line (ไม่ต้องเปิด Android Studio)
PowerShell (แก้ path ให้ตรงเครื่อง):
```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
cd app
npm install
npm run sync
cd android
.\gradlew.bat assembleDebug
```

### 4.4 เวอร์ชันใช้งานจริง (release)
1. Android Studio → **Build → Generate Signed App Bundle / APK** → APK → สร้าง keystore ใหม่ **เก็บไฟล์และรหัสไว้ให้ดี** (ถ้าหาย จะอัปเดตแอปทับของเดิมไม่ได้)
2. ก่อน build release ให้แก้ `app/capacitor.config.json` เป็น `"webContentsDebuggingEnabled": false` แล้ว `npm run sync`
3. ถ้าจะใช้ชื่อแพ็กเกจขององค์กร ให้เปลี่ยน `th.co.walkie.app` (appId ใน config, `namespace`/`applicationId` ใน `android/app/build.gradle` และชื่อแพ็กเกจของไฟล์ Java) **ก่อน** แจกจ่ายครั้งแรก

ทุกครั้งที่แก้ `server/public/index.html` ให้รัน `npm run sync` ใน `app/` ก่อน build

## 5. ติดตั้งลงมือถือ

**วิธี A: สาย USB (เหมาะกับเครื่องทดสอบ)**
1. มือถือ: ตั้งค่า → เกี่ยวกับโทรศัพท์ → แตะ "หมายเลขรุ่นสร้าง" 7 ครั้ง → เปิด **ตัวเลือกสำหรับนักพัฒนา → การแก้ไขข้อบกพร่อง USB**
2. เสียบสาย แล้วกดยอมรับบนมือถือ
3. ติดตั้ง:
   ```powershell
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r app\android\app\build\outputs\apk\debug\app-debug.apk
   ```
   หรือกดปุ่ม ▶ Run ใน Android Studio

**วิธี B: ส่งไฟล์ APK** (LINE / อีเมล / แชร์ไดรฟ์ภายใน)
1. เปิดไฟล์บนมือถือ
2. ระบบจะถามให้อนุญาต "ติดตั้งแอปที่ไม่รู้จัก" จากแอปที่ใช้เปิดไฟล์ ให้อนุญาต
3. กดติดตั้ง ถ้า Play Protect เตือนว่าไม่รู้จักผู้พัฒนา ให้เลือก "ติดตั้งต่อไป"

**วิธี C: องค์กรที่มี MDM** (เช่น Samsung Knox Manage, Intune) อัปโหลด APK ที่ลงลายเซ็นแล้ว แล้วกระจายให้ทุกเครื่องได้เลย

### ตั้งค่าครั้งแรกในแอป
1. ใส่ที่อยู่เซิร์ฟเวอร์ เช่น `192.168.1.10:3000` แล้วกด **ตรวจสอบ**
2. ถ้าขึ้นกล่องใบรับรอง self-signed ให้เทียบลายนิ้วมือกับหน้าจอเซิร์ฟเวอร์ ตรงกันแล้วจึงกด **เชื่อถือ**
3. ใส่ชื่อ เลือกช่อง แล้วกด **เข้าช่อง** จากนั้นอนุญาต **ไมโครโฟน** และ **การแจ้งเตือน**
4. แอปจะเปิดหน้า "ตั้งค่าเครื่อง" ให้กด **ปิดการประหยัดแบตเตอรี่ของแอป** → อนุญาต แล้วทำตามคำแนะนำของยี่ห้อเครื่อง

## 7. สิ่งที่แก้ใน server.js (เว็บเดิมยังใช้ได้)

โปรโตคอลข้อความ**ไม่เปลี่ยน** แก้เพิ่มแค่นี้:
1. **Heartbeat**: เซิร์ฟเวอร์ ping ทุก 20 วิ ถ้าไม่มี pong กลับจะตัดการเชื่อมต่อ เดิมมือถือที่หลุด Wi-Fi จะค้างเป็นผีในช่อง และถ้าหลุดตอนพูดจะถือสิทธิ์พูดค้างไว้ถึง 60 วิ เบราว์เซอร์ทุกตัวและแอปตอบ ping อัตโนมัติ จึงใช้กับเว็บเดิมได้
2. **แก้บั๊ก timer**: เดิมถ้าคนที่พูดอยู่ส่ง `ptt_start` ซ้ำ timer 60 วิอันเก่าไม่ถูกยกเลิก จึงถูกตัดเร็วกว่ากำหนด (มีเทสต์ยืนยัน: เซิร์ฟเวอร์เดิมตกเทสต์นี้ ตัวใหม่ผ่าน)
3. พิมพ์ลายนิ้วมือใบรับรองตอนเริ่ม เมื่อใช้ HTTPS
4. ค่า `WALKIE_HEARTBEAT_MS`, `WALKIE_MAX_TALK_MS` ตั้งผ่าน env ได้ (ใช้ในเทสต์ ค่าปกติเท่าเดิม)

แก้บั๊กในหน้าเว็บเดิมด้วย: เดิมถ้ากดเข้าช่องแล้ว**ปฏิเสธไมค์ครั้งแรก** แล้วอนุญาตทีหลัง กดเข้าช่องใหม่จะเข้าได้ แต่ส่งเสียงไม่ออก (โค้ดข้ามขั้นตอนตั้งค่าไมค์) ตอนนี้แก้แล้ว

## 8. ข้อจำกัดและเรื่องความปลอดภัย

- **ws:// ไม่เข้ารหัส**: แอปอนุญาต cleartext เพื่อใช้ใน LAN ได้ทันที ใครอยู่ใน Wi-Fi เดียวกันดักฟังได้ ถ้าเนื้อหาสำคัญให้ใช้ wss (`npm run cert`)
- **ยังไม่มีการยืนยันตัวตน** (เหมือนเดโมเดิม) ใครรู้ที่อยู่เซิร์ฟเวอร์ก็เข้าช่องได้
- **มือถือบางยี่ห้อ** (Xiaomi, OPPO, vivo, Huawei, Samsung บางรุ่น) ยังปิดแอปเบื้องหลังได้แม้ทำทุกอย่างถูกแล้ว ต้องตั้งค่าตามยี่ห้อ (มีในหน้าตั้งค่าเครื่อง) ดูรายละเอียดรายยี่ห้อได้ที่ dontkillmyapp.com
- **แบตเตอรี่**: WakeLock + WifiLock + ping ทุก 15 วิ กินแบตมากกว่าแอปทั่วไป ควรทดสอบว่าใช้ได้ครบกะงาน
- **ถ้าระบบฆ่า service** แล้วสั่งเริ่มใหม่เอง (START_STICKY) ตอนแอปไม่ได้อยู่หน้าจอ Android 12+ อาจไม่ยอมให้เริ่ม foreground service ใหม่ แอปจะหยุด ผู้ใช้ต้องเปิดแอปแล้วเข้าช่องใหม่ ส่วน Android 11+ จะไม่ยอมให้เปิดไมค์ใน service ที่เริ่มจากเบื้องหลัง กรณีนั้นจะฟังได้อย่างเดียวจนกว่าจะเปิดแอป
- **ปุ่มหูฟัง**: ระหว่างเปิดตัวเลือกนี้ แอปจะรับปุ่ม play/pause ไว้เอง ปุ่มนี้จะไม่ควบคุมแอปเพลง ถ้าไม่ต้องการให้ปิดในหน้าตั้งค่าเครื่อง
- **Google Play**: ถ้าจะลง Play Store ต้องชี้แจงการใช้ foreground service และ `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` ตามนโยบาย ถ้าแจกภายในองค์กร (APK/MDM) ไม่ติดเรื่องนี้

## 9. iOS

ทำแบบเดียวกันบน iPhone **ไม่ได้** ด้วยวิธีนี้ เพราะ iOS ไม่มี foreground service แบบ Android:
- แอปที่ไม่ได้อยู่หน้าจอจะถูกพักภายในไม่กี่วินาที WebSocket หลุด จึงรับเสียงไม่ได้ (โหมด background audio ใช้ได้เฉพาะตอนกำลังเล่นเสียงอยู่จริง และ Apple ไม่ให้ใช้เพื่อเปิดค้างไว้รอเสียง)
- Apple กำหนดให้แอปวอใช้ **PushToTalk framework** (iOS 16+) ร่วมกับ **APNs push แบบ pushtotalk** ให้ระบบปลุกแอปเมื่อมีคนเริ่มพูด และแสดง UI พูดของระบบบนจอล็อก
- ต้องมีงานแยกต่างหาก:
  - แอป iOS native (Swift)
  - entitlement Push to Talk และ Background Modes (push-to-talk)
  - เซิร์ฟเวอร์ต้องเก็บ PTT push token ของแต่ละเครื่อง และส่ง APNs ตอนมีคนเริ่มพูด (ต้องมีบัญชี Apple Developer และใบรับรอง APNs)
  - ปรับลำดับการรับเสียงให้รองรับช่วงที่ระบบกำลังปลุกแอป
- ระหว่างนี้ ผู้ใช้ iPhone ใช้เว็บเวอร์ชันได้ตามเดิมเฉพาะตอนเปิดหน้าเว็บค้างไว้

  - ไม่มี JavaScript error
- **หน้าเว็บใหม่กับเซิร์ฟเวอร์ LAN เดิม:** ไม่ถามรหัส, เข้าช่องได้, ห้องสนทนาบอกว่าแชทพิมพ์ใช้ได้เฉพาะ Cloudflare
- **คอนทราสต์** ธีมใหม่ทั้งสอง ผ่าน 42/42 คู่ต่อธีม
- ไวยากรณ์ JavaScript ทุกไฟล์ และ Java ทุกไฟล์ (หลังเพิ่มรหัส/แชทในแอป Android) ผ่าน

### ⚠️ ยังไม่ได้ทดสอบ: Cloudflare + PWA
- **ติดตั้ง PWA บนมือถือจริง** (Android Chrome / iPhone Safari) เพราะเบราว์เซอร์ในแอปที่ใช้ทดสอบไม่ยอมลงทะเบียน service worker (ไฟล์ sw.js ตอบ 200 และไวยากรณ์ถูก)
- เสียงจริงผ่านอินเทอร์เน็ต (มือถือ 4G/5G ↔ Wi-Fi) และความหน่วง
- โหมด "ฟังต่อเมื่อปิดจอ (ทดลอง)" และปุ่มหูฟังใน PWA บนเครื่องจริง
- การเด้งแจ้งเตือนของระบบ (Notification) ตอนแอปอยู่เบื้องหลัง
- สแกน QR ในแอป (ใช้ BarcodeDetector มีใน Chrome Android ไม่มีใน iPhone ให้ใช้กล้องของเครื่องแทน)
- งาน cron ลบข้อมูลเก่า (รันครั้งแรกตี 3 คืนนี้)

### ✅ ทดสอบแล้ว: งานรอบแรก (บนคอมเครื่องนี้)
- **โปรโตคอลเซิร์ฟเวอร์** `npm test` ผ่าน 8/8 ข้อ
  - join / state
  - พูดทีละคน + busy
  - ส่งเสียงต่อเฉพาะคนที่ถือสิทธิ์
  - หมดเวลาพูด
  - คนพูดหลุดแล้วปล่อยสิทธิ์
  - heartbeat ตัดเครื่องที่ไม่ตอบ ping
  - client ปกติไม่ถูกตัด
  - `/api/channels`
  - รันซ้ำ 3 รอบ ผ่านทุกรอบ เทสต์บั๊ก timer ตกกับ server.js เดิม และผ่านกับตัวใหม่
- **HTTPS/wss**:
  - สร้างใบรับรองด้วย openssl แล้วเซิร์ฟเวอร์พิมพ์ลายนิ้วมือได้ถูก ตรงกับ `openssl x509 -fingerprint -sha256` และตรงกับใบรับรองที่ client wss ได้รับจริง
  - รูปแบบตรงกับที่แอปแสดง: ตัวพิมพ์ใหญ่ คั่นด้วย `:`
- **คอนทราสต์ WCAG AA** ทั้งสองธีม (`node tools/check-contrast.js`) ผ่านทุกคู่
- **เว็บเวอร์ชัน** ในเบราว์เซอร์ (ขนาดจอมือถือ 375px):
  - ทั้งสองธีมแสดงถูก ไม่มี scroll แนวนอน
  - สลับธีมแล้วจำค่าได้ `aria-label` และ `theme-color` เปลี่ยนตาม
  - สถานะว่าง/กำลังพูด(แดง)/กำลังรับฟัง(เขียว) ถูกทั้งสองธีม
  - คุยจริงกับ client ตัวที่สองผ่านเซิร์ฟเวอร์: ส่งเสียงออก 36 ชิ้น และเล่นเสียงขาเข้าได้ ใช้ไมค์จำลองแทน เพราะหน้าต่างทดสอบไม่มีไมค์
  - กรณีปฏิเสธไมค์ครั้งแรกแล้วลองใหม่ (บั๊กที่แก้) ใช้ได้แล้ว
- **โหมดแอปของหน้าเว็บ** ทดสอบกับ plugin จำลองที่ทำตัวแบบ service และต่อเซิร์ฟเวอร์จริง:
  - ตรวจสอบที่อยู่: ผิดพลาด / self-signed → ยืนยันลายนิ้วมือ → เชื่อมต่อได้
  - เข้าช่อง → หน้าตั้งค่าเครื่องเปิดเอง → สวิตช์ปุ่ม และปุ่มเปิดตั้งค่าแบตส่งคำสั่งถูก
  - กดพูดด้วย pointer events → ปล่อย
  - สถานะ reconnect, สลับช่อง, ออกจากช่องจากการแจ้งเตือน
  - เปิดแอปกลับมาขณะ service ยังทำงาน → กลับเข้าหน้าช่องพร้อมคนที่กำลังพูด
  - ไม่มี error ใน console
- **โค้ด Java**: ตรวจ syntax ทุกไฟล์ผ่าน (ด้วย java-parser) และตรวจชื่อ/รูปแบบ API ของ Capacitor 8 กับซอร์สใน `node_modules`
- `npx cap add android` และ `npm run sync` ทำงานได้ หน้าเว็บในแอปตรงกับ `server/public/index.html`

### ⚠️ ยังไม่ได้ทดสอบ (ต้องทำบนเครื่องจริง)
- **ยังไม่ได้คอมไพล์ APK** เพราะเครื่องนี้ไม่มี JDK และ Android SDK ส่วนนี้ตกลงกันว่าจะไม่ติดตั้ง Java ยังไม่ผ่านคอมไพเลอร์จริง ครั้งแรกที่ build อาจเจอ error คอมไพล์เล็กน้อยที่ต้องแก้
- ทุกข้อในตารางหัวข้อ 6 โดยเฉพาะ:
  - จอล็อกนาน 30 นาทีขึ้นไป (ข้อ 6)
  - ปัดแอปทิ้ง (ข้อ 5)
  - Wi-Fi หลุดแล้วต่อกลับ (ข้อ 7)
  - ทดสอบบนหลายยี่ห้อ: Samsung, Xiaomi, OPPO
- คุณภาพเสียงจริง: ความดัง, เสียงสะท้อน, ความหน่วง (jitter buffer 80 ms)
- เสียงจาก AudioRecord แหล่ง VOICE_COMMUNICATION บนแต่ละรุ่น
- ปุ่มหูฟังมีสาย/Bluetooth ตอนจอล็อก: ปุ่มจะมาถึงแอปเราหรือไม่ ขึ้นกับว่าแอปไหนเล่นเสียงล่าสุด
- ปุ่ม XCover/Sonim: ชื่อ broadcast และ keycode อ้างอิงจากเอกสารของผู้ผลิตและแอป PTT อื่น ยังไม่ได้ลองกับเครื่องจริง XCover อาจต้องตั้งค่าใน "ปุ่ม XCover" หรือผ่าน Knox
- Android 14/15/16: การเริ่ม FGS ประเภท microphone, การขอสิทธิ์แจ้งเตือน, การแจ้งเตือนบนจอล็อก
- ปุ่ม "กดพูด" ในการแจ้งเตือนจากจอล็อก
- การกินแบตตลอดกะงาน 8 ชั่วโมง
- การ pin ใบรับรอง self-signed กับ OkHttp จริง และ wss ผ่าน IP ที่ไม่ตรง CN
